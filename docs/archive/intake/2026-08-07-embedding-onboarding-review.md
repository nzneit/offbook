## c — No version identity anywhere; skill staleness and teammate skew are undetectable; `skill install` semantics under-pinned.
There is no `offbook --version`; `bun link` makes the tool a live symlink to a personal checkout, so it changes under users silently (FMEA A4/B1/I2/I3; adversarial 4/7). The committed skill copy has no freshness signal, and the design never states whether adopter-customized copies are legitimate (in which case blind `--force` is destructive). Recommendation, as one package: `offbook --version` reporting version + source commit of the linked checkout; `skill install` stamps that identity into the installed `SKILL.md`; a doctor check compares installed vs bundled and hints `offbook skill install --force`; pin the verb semantics — "different" = byte-level tree equality, `--force` = clean-replace (overlay would orphan old files and jam every future compare), present-different refusal exits 1, bare `offbook skill` prints a subcommand usage error and exits 1; §6's test list gains each case.
→ Resolution: **the package, with mechanics concretized** (decided 2026-08-08). (1) `offbook --version` handled at dispatch before verb lookup: `offbook <pkg version> (<short-sha>[-dirty])`, sha via git in the `import.meta.dir`-resolved repo root, `unknown` fallback. (2) The provenance stamp (version, sha, install date, source path) lives in a dedicated `.installed-from` file inside the installed dir — **not** SKILL.md — so the staleness compare stays byte-exact against the bundled source with a trivial exclusion rule. (3) Doctor check 8 `skill`: resolve the git toplevel from the examined dir; absent = pass (detail names `offbook skill install`); identical = pass; different = **warn** (never fail) with hint `offbook skill install --force`. (4) "Different" = byte-level tree equality (file set + contents, stamp excluded); `--force` = clean-replace (remove dir, re-copy), never overlay; present-different refusal exits 1; bare/unknown `offbook skill` subcommand prints usage, exits 1; each case joins §6's `src/cli/skill.test.ts` list. Stance recorded: installed-copy edits are **drift, not customization** — the skill is a derived artifact; local edits belong upstream in `skills/onboard/`; the doctor warn + show-divergence-before-`--force` keeps a deliberate customizer from silent clobbering, but no permanent-fork/three-way-merge story at n=1. Amends adoption.md §3 (check table gains 8), §9 (verb semantics + stamp), §6 (test list), R-042's statement.

## e — The verb-existence gate is unspecified on both ends (USAGE source, extraction grammar), and USAGE is not dispatch truth.
`USAGE` is a non-exported literal; check-docs is deliberately dependency-free, so importing the CLI module vs scraping the literal are materially different designs; `demo` is special-cased outside the `VERBS` table, and nothing pins USAGE ↔ dispatch coherence, so a verb dead in dispatch can keep skill references falsely alive. Extraction has no grammar: `offbook <cmd>`-style placeholders would false-positive; subcommands (`specs update`, `skill install`) are unchecked. Recommendation: export one `VERB_NAMES` array that USAGE, dispatch, and the checker all derive from (closes the coherence gap as a side effect); extraction grammar = backtick-fenced `offbook <token>` with `<...>`-placeholder forms exempt; enumerate the known two-token forms; state the residual subcommand blind spot in §9.
→ Resolution: **one source of truth, three consumers** (decided 2026-08-08). (1) A leaf module `src/cli/verbs.ts` exports `VERB_FORMS`: every valid invocation form, one- and two-token (`"specs"` and `"specs update"` both valid; bare `"skill"` deliberately absent per fork c — only `"skill install"`). Imports nothing, so check-docs importing it keeps the checker's zero-dependency spirit (the objection was the CLI index and its transport stack, not a dependency-free leaf). (2) Coherence pinned by test in both directions: VERB_FORMS' first tokens ≡ dispatch-table keys ∪ {`demo`}; every form appears in USAGE and no USAGE verb line names a form outside the list — closing the USAGE↔dispatch gap for the whole CLI as a side effect. (3) Extraction grammar: check-docs scans `skills/onboard/**` inline backtick spans + fenced code blocks for `offbook …`; `<...>` tokens are placeholders (exempt), leading-dash tokens are flags (ignored); if the first token belongs to a subcommand-taking verb (derivable from VERB_FORMS), the **two-token** form must match — so dead `skill uninstall` or bare `skill` in skill text fails; otherwise the first token must match. (4) Residual stated in §9: verb *forms* only — flag names and argument semantics unchecked (the doctor check-5-note genre). Scrape-USAGE-with-regex rejected: inherits USAGE's untruth, adds a brittle parser, fixes nothing else. Amends adoption.md §9 (rot gates), §6, R-042's statement.

## f — `skill install [dir]` inverts the meaning `[dir]` has on every other verb, and two silent propagation killers go unwarned.
`doctor [dir]`/`init [dir]` take the offbook project dir (`mock/`); `skill install [dir]` takes the app-repo root. Run in `mock/` it produces `mock/.claude/skills/`, which a session at the repo root never discovers — silently. A repo that gitignores `.claude/` silently defeats "self-propagating" (the install "succeeds", the commit omits it). Recommendation: default the destination to `git rev-parse --show-toplevel`; warn when the destination is nested below the toplevel or when `git check-ignore` says the target path is ignored.
→ Resolution: **one step past the recommendation — the positional is dropped entirely** (decided 2026-08-08). (1) `offbook skill install` takes no positional: the destination is `git rev-parse --show-toplevel` from the cwd, always; outside a git repo it errors with a next step ("not inside a git repository — cd into your app repo") since a skill outside a repo cannot propagate and the app repo is by definition a clone. (2) `--dest <dir>` is the explicit escape hatch for unusual layouts (monorepo sessions opening at a subdir) — a flag named "dest" cannot be confused with "project dir", and the different argument shape *signals* the different semantics; the `[dir]`-redefault alternative was rejected because it fixes only the no-args case while `skill install mock/` still silently does the wrong thing. (3) Two non-fatal warnings, each naming its consequence: `--dest` below a repo's toplevel ("a session at the repo root won't discover a skill installed here"); target path gitignored per `git check-ignore` ("`.claude/` is gitignored here — the skill won't propagate; un-ignore it or teammates never see it"). Warn-and-proceed, not refuse: both states can be intentional; the warning converts silent defeat into informed choice. Amends adoption.md §9 (distribution bullet), §6 (test cases), R-042's statement; doctor check 8 already resolves the toplevel identically (fork c), unchanged.
