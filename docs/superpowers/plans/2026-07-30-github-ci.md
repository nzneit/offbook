# GitHub CI Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Enforce the existing local gate set on GitHub: a `gates` check on every PR targeting `main`, the same gates plus build artifacts on every push to `main`, and a branch ruleset that makes the check required.

**Architecture:** One workflow file, one serial job (the full gate set runs in ~40 s locally, so parallel jobs would only add runner-boot overhead). Artifact uploads are steps guarded by `if: github.event_name == 'push'`. Enforcement is a branch ruleset created once via `gh api`, with a Repository-admin bypass so the owner keeps direct pushes.

**Tech Stack:** GitHub Actions (`actions/checkout@v7`, `oven-sh/setup-bun@v2`, `actions/upload-artifact@v7`), Bun 1.3.14, `gh` CLI for ruleset + verification.

**Spec:** `docs/superpowers/specs/2026-07-30-github-ci-design.md` (approved 2026-07-30).

## Global Constraints

- Bun is pinned to exactly `1.3.14` in CI (bunfig coverage-gate semantics were verified on that version; bumping is a deliberate one-line PR).
- Action versions: `actions/checkout@v7`, `oven-sh/setup-bun@v2`, `actions/upload-artifact@v7` (majors verified current 2026-07-30).
- Required check context is the job id `gates`; the ruleset targets `~DEFAULT_BRANCH` with strict up-to-date and a Repository-admin bypass (`actor_id: 5`).
- Mutation testing must NOT appear in CI in any form (no `workflow_dispatch` either). No release automation, no dependency caching, no compiled-binary artifact (deferred; see spec Known limitations).
- Commit messages: conventional prefixes (`feat:`/`fix:`/`docs:`/`ci:`), imperative, no Co-Authored-By or AI-attribution trailers, ever.
- Never run `git config user.*`. Push only where a step says to push.
- After ANY edit to `DECISIONS.md`, `AGENTS.md`, or `README.md`, `bun scripts/check-docs.ts` and full `bun test` must stay green before committing (README has an executable quickstart gate; check-docs validates ledger ids).
- `bun test <single-file>` may exit 1 with zero failures (per-file coverage floor). Gate on full `bun test` runs only.

### Task 1: The workflow file and the `typecheck` script

**Files:**
- Create: `.github/workflows/ci.yml`
- Modify: `package.json` (scripts block, currently lines 17-23)

**Interfaces:**
- Produces: a check run named `gates` on PRs targeting main and pushes to main (Task 3's ruleset requires this exact context string), artifacts `demo-app-dist` and `coverage` on main pushes (Task 2 verifies them), and the package script `typecheck` (used by the workflow and by humans).

- [ ] **Step 1: Create `.github/workflows/ci.yml`**

Exact content:

```yaml
name: ci
on:
  pull_request:
    branches: [main]
  push:
    branches: [main]
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}  # never cancel main runs
permissions:
  contents: read
jobs:
  gates:
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - uses: actions/checkout@v7
      - uses: oven-sh/setup-bun@v2
        with:
          bun-version: "1.3.14"  # pinned: coverage-gate semantics verified on this version (see bunfig.toml)
      - run: bun install --frozen-lockfile
      - run: bun scripts/check-docs.ts   # doc-system gate
      - run: bun run lint                # Biome, incl. transport isolation
      - run: bun run typecheck           # tsc --noEmit
      - run: bun run demo-app:build
      - run: bun test                    # authoritative full run; carries the coverage floors
      - if: github.event_name == 'push'
        uses: actions/upload-artifact@v7
        with: { name: demo-app-dist, path: demo-app/dist/, retention-days: 14 }
      - if: github.event_name == 'push'
        uses: actions/upload-artifact@v7
        with: { name: coverage, path: coverage/, retention-days: 14 }
```

### Task 3: Create the branch ruleset

**Files:** none (repo settings via API; the JSON is recorded here and in the spec).

**Interfaces:**
- Consumes: the check context `gates` (Task 1) and an authenticated admin `gh` (Task 0).
- Produces: enforced merges on `main`; Task 4 relies on PR merge being blocked until `gates` passes.

- [ ] **Step 1: Create the ruleset**

```bash
gh api repos/nzneit/offbook/rulesets --method POST --input - <<'JSON'
{
  "name": "main gates",
  "target": "branch",
  "enforcement": "active",
  "bypass_actors": [
    { "actor_id": 5, "actor_type": "RepositoryRole", "bypass_mode": "always" }
  ],
  "conditions": { "ref_name": { "include": ["~DEFAULT_BRANCH"], "exclude": [] } },
  "rules": [
    {
      "type": "required_status_checks",
      "parameters": {
        "strict_required_status_checks_policy": true,
        "required_status_checks": [ { "context": "gates" } ]
      }
    }
  ]
}
JSON
```

Expected: HTTP 201 with a JSON body echoing the ruleset (note the `id`). If the API rejects a field name, run `gh api repos/nzneit/offbook/rulesets --method GET` on any existing ruleset and compare shapes; the schema above matches the 2022-11-28 REST version.

- [ ] **Step 2: Verify the effective rules on main**

```bash
gh api repos/nzneit/offbook/rules/branches/main --jq '.[].type'
```

Expected: output includes `required_status_checks`.

Note: this endpoint reports rules as they apply to the calling user; if the bypass makes it come back empty, verify instead with `gh api repos/nzneit/offbook/rulesets --jq '.[].name'` (expect `main gates`) and proceed; Task 4 Step 4 is the behavioral proof.

```markdown
### D-017: CI on GitHub Actions: one `gates` workflow job, artifacts on main pushes, branch-ruleset enforcement
**Date**: 2026-07-30
**What**: `.github/workflows/ci.yml` runs a single `gates` job on PRs targeting `main` and on pushes to `main`: `bun install --frozen-lockfile`, then `check-docs` → `lint` → `typecheck` (new package.json script, `tsc --noEmit`) → `demo-app:build` → full `bun test`, on Bun pinned to exactly 1.3.14; main-push runs additionally upload `demo-app/dist/` and `coverage/` as 14-day artifacts. A branch ruleset on `main` requires the `gates` check with strict up-to-date, with a Repository-admin bypass so direct owner pushes stay possible. Mutation testing is excluded from CI in any form; no release automation and no dependency caching.
**Why**: The full local gate set existed but nothing enforced it at merge time. One serial job because the whole set runs in ~40 s locally, so parallel jobs would only add per-job runner boot and install overhead. Bun is pinned because the bunfig.toml coverage-gate semantics (per-file floors; silent exit-1 as the only failure signal) were empirically verified on 1.3.14, and a floating runtime could silently change what the test gate means; bumping the pin is a deliberate one-line PR the gates themselves validate. A compiled-binary artifact was dropped after two verified findings (the extensionless `bin/offbook` makes `bun build --compile` emit a 1-module no-op binary, and with that fixed the Spectral/nimma dynamic `require()`s still break the compiled binary at startup: `Cannot find module './impl/format'`); single-binary offbook is deferred as its own project.
**From**: docs/superpowers/specs/2026-07-30-github-ci-design.md (design dialog, 2026-07-30)
**Folds into**: .github/workflows/ci.yml, package.json (`typecheck`), AGENTS.md (working notes), README.md (badge)
```
