## c — No version identity anywhere; skill staleness and teammate skew are undetectable; `skill install` semantics under-pinned.
There is no `offbook --version`; `bun link` makes the tool a live symlink to a personal checkout, so it changes under users silently (FMEA A4/B1/I2/I3; adversarial 4/7). The committed skill copy has no freshness signal, and the design never states whether adopter-customized copies are legitimate (in which case blind `--force` is destructive). Recommendation, as one package: `offbook --version` reporting version + source commit of the linked checkout; `skill install` stamps that identity into the installed `SKILL.md`; a doctor check compares installed vs bundled and hints `offbook skill install --force`; pin the verb semantics — "different" = byte-level tree equality, `--force` = clean-replace (overlay would orphan old files and jam every future compare), present-different refusal exits 1, bare `offbook skill` prints a subcommand usage error and exits 1; §6's test list gains each case.
→ Resolution: _open_

## d — The installed skill cannot reach the docs it defers to, and "no chicken-and-egg" overclaims; the second teammate has the skill but not the tool.
Relative links from `<appRepo>/.claude/skills/offbook-onboard/` back to offbook's guides resolve to nothing (and the §9 link gate validates them against the *offbook* tree — the wrong filesystem); the shipped skill cannot name the internal clone URL (the `<internal-git>` placeholder rule forbids inventing one); FMEA I1: a fresh app-repo clone has `mock/`, scripts, and skill, but `offbook: command not found` and nothing committed names the fix. Recommendation, as one package: `skill install` stamps the source checkout path and `git remote get-url origin` into the installed copy; intra-skill relative links only (and gate exactly that); scope §9's claim to "installable before any offbook *project* exists in the app repo"; `offbook init` scaffolds a short `mock/README.md` (what this dir is; install offbook: clone/`bun install`/`bun link`; `offbook doctor` first; guide pointers) so the app repo names the next step for teammates with or without an agent.
→ Resolution: _open_

## e — The verb-existence gate is unspecified on both ends (USAGE source, extraction grammar), and USAGE is not dispatch truth.
`USAGE` is a non-exported literal; check-docs is deliberately dependency-free, so importing the CLI module vs scraping the literal are materially different designs; `demo` is special-cased outside the `VERBS` table, and nothing pins USAGE ↔ dispatch coherence, so a verb dead in dispatch can keep skill references falsely alive. Extraction has no grammar: `offbook <cmd>`-style placeholders would false-positive; subcommands (`specs update`, `skill install`) are unchecked. Recommendation: export one `VERB_NAMES` array that USAGE, dispatch, and the checker all derive from (closes the coherence gap as a side effect); extraction grammar = backtick-fenced `offbook <token>` with `<...>`-placeholder forms exempt; enumerate the known two-token forms; state the residual subcommand blind spot in §9.
→ Resolution: _open_

## f — `skill install [dir]` inverts the meaning `[dir]` has on every other verb, and two silent propagation killers go unwarned.
`doctor [dir]`/`init [dir]` take the offbook project dir (`mock/`); `skill install [dir]` takes the app-repo root. Run in `mock/` it produces `mock/.claude/skills/`, which a session at the repo root never discovers — silently. A repo that gitignores `.claude/` silently defeats "self-propagating" (the install "succeeds", the commit omits it). Recommendation: default the destination to `git rev-parse --show-toplevel`; warn when the destination is nested below the toplevel or when `git check-ignore` says the target path is ignored.
→ Resolution: _open_

## g — FMEA top gaps: adopt as design obligations, and decide where they land (fold into R-041/R-042 scope, or allocate an R-043).
1. **Connected-clients surface** (the one CRITICAL: the app silently talks to the reachable real backend while offbook runs empty — the abandon-the-tool scenario). Connect fingerprints already land in offbook.log (D-015); `offbook status` gains a "clients: N (last connect …)" line, and the wiring guide's first-light section + skill step 6 make "watch your app's connect fingerprint land" the explicit acceptance test.
2. **Cross-run-dir misattribution at first light**: the Stage-A demo still holds the ports; preflight/doctor call it a foreign process. When the ctrl port is busy, probe it with the existing `probeOffbook`; if it answers, say "an offbook from another directory owns these ports (likely the demo) — run `offbook down` there, or pass --ws-port/--ctrl-port".
3. **Silent staleness in the advertised loops**: `specs update` never re-reads an edited services.yaml (new services silently never appear while "specs refreshed" prints success) — record a services.yaml hash at boot and warn "changed since `up` — restart to apply"; `offbook topics --json` with no server silently returns the bundled demo spec — add an explicit `source: "bundled-demo"` marker or refuse in `--json` mode (the skill's ingestion check reads this).
4–5. mock/README.md scaffold and the version surface — folded into forks **d** and **c**.
Runners-up recorded, not allocated: offline/cached `up` when the git host is down (F4); a complete CI recipe (install steps + cleanup-on-failure, H1/H2 — plus `offbook check --since` for suites with deliberate bad publishes, H3); a cwd/run-dir note in daily-loop.md (F1); `init` appending `.offbook/` to an existing `.gitignore` instead of skipping (C2); a stated specs.lock VCS stance in the wiring guide (C4); doctor's specs-reachable hint acknowledging auth failures and the specPath blind spot (D4/D5).
→ Resolution: _open_
