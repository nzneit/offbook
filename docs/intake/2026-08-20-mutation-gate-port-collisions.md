# 2026-08-20: mutation-gate port-collision nondeterminism (intake)
**Status**: open
**Owner**: repo owner (gate infra, D-027 territory)

## a — concurrent mutant runs collide on the suite's fixed test ports
The CI gate runs Stryker at `--concurrency 4` (Task-10-measured; conc-1 exceeded the 15-minute job timeout). Each worker runs `bun test` against the same test files, and the suite's ports are fixed and unique **per file**, not per worker — so two workers running the same covering test bind the same ports and one dies with `EADDRINUSE`. PR #19's gate job showed this repeatedly ("Failed to start server. Is port 19001 in use?" mid-run, plus `WARN BunTestRunner Mutant N: no killing test identifiable — emitting empty killedBy`). A crashed run is scored as a kill, so the gate is nondeterministic in **both** directions: crash-luck kills mutants that are genuinely equivalent (observed: `resolve.ts` 217/348 and `runfile.ts` 57 killed with empty `killedBy` in one run), and schedule-luck lets genuinely killable mutants survive a later run (observed: the registry dedupe `MethodExpression` mutant, killed in three runs, survived the fourth — that instance was readdir-order dependence, fixed at the product level by sorting the scan, but the port-collision class remains). A second effect: a mutant that breaks server cleanup leaves an orphaned `.stryker-tmp/sandbox-*/src/cli/serve.ts` squatting fixture ports, poisoning every later run in the job (see the AGENTS.md working note).
Options: (1) **per-worker port namespacing** — Stryker core sets `STRYKER_MUTATOR_WORKER` in each worker's env (`@stryker-mutator/core` `child-process-proxy.js`), and the bun-test child inherits it; a small test helper deriving a per-worker offset (e.g. `+ 2000 × worker`) applied to the port-heavy files would make concurrent runs collision-free while keeping conc-4 throughput. (2) `--concurrency 1` — eliminates cross-worker collisions but not orphan poisoning, and Task 10 measured it over the job timeout. (3) Accept the noise — rejected: it already flipped a required check both ways on one PR.
Recommendation: option 1, in its own PR (it sweeps port literals across many test files and deserves its own measurement + review round), plus a defensive orphan sweep step at the end of the gate job.
