Both are cheap to fix in the CLI/onboarding surface.

## Tier 1 — the cold start

### EI1 — there is no scaffold; "one command" is false on a fresh clone
- **Where:** `offbook-design.md` §9 moment-1 (line ~280); `offbook-contracts.md` §6 `services.yaml` / `environments.yaml` (lines ~357–378), `gitHost` has **no default** and a slug without it is a config error (line ~358); build-plan Tier 4 CLI (line ~87).
- **Problem:** before `offbook up` does anything a dev must author `services.yaml` (with `gitHost` + per-service repo/specPath) and `environments.yaml`, and have working git creds. There is no command that produces these. "Zero-to-running with one command" is not achievable on a cold clone unless someone already committed the config.
- **If unaddressed:** onboarding is multi-step config archaeology against an under-documented schema; the moment-1 promise doesn't hold and first impressions suffer.
- **Decision owed:** scope of `init` — minimal non-interactive stub emission vs interactive prompts (gitHost, service discovery). *Recommend minimal non-interactive* (predictable, scriptable; interactive can come later).
- **Recommended resolution:** `offbook init [--dir .]` writes, only if absent, refusing to overwrite:
  ```
  services.yaml              # gitHost: <PLACEHOLDER> + one commented example service block
  environments.yaml          # default env with a commented service:version line
  scenarios/00-example.yaml  # a runnable sample scenario (the offbook-l2-scenarios.md §0 example)
  ```
  Then prints next steps: `edit services.yaml (set gitHost + your services), then: offbook up`. Note: do **not** scaffold or gitignore `specs.lock` — it is generated by `up` and committed.
- **Acceptance:** in an empty dir, `offbook init` creates the three files and exits 0; re-running refuses to overwrite (nonzero, names the existing files); with the example service repo reachable, `offbook init && <edit gitHost> && offbook up` reaches a running server with no other hand-authored YAML.
- **Status:** ☑ **resolved** (2026-06-30) — minimal non-interactive `offbook init [--dir .]`: writes (only if absent, refusing to overwrite) `services.yaml` (`gitHost: <PLACEHOLDER>`), `environments.yaml`, `scenarios/00-example.yaml`, **+ an empty `handlers/`** (so `up --watch` has a target) **+ a `.gitignore`** for the run artifacts (`<runDir>`/`offbook.log`/runfile; `specs.lock` stays tracked); prints next steps; never scaffolds `specs.lock`. Folded → design §9, contracts §6 (cross-ref), build-plan Tier 4.

## Tier 2 — first-run honesty

### EI2 — the first run doesn't set the "spec gives structure, humans give behavior" expectation
- **Where:** `offbook-design.md` §4 framing (line ~119: "the spec gives you validation and structure; humans give you behavior"); §9 moment-1.
- **Problem:** the design explicitly wants the first-run experience to set honestly that L1 is a schema-valid *floor* and the development value is authored in L2/L3. No surface communicates this; a fresh run shows only schema-filler responses.
- **If unaddressed:** a dev sees generic filler, concludes "these are just dumb mocks," and never reaches for L2 scenarios / L3 handlers — the tool stalls at the floor (design §10's stated risk).
- **Decision owed:** none — mechanical (where the line appears: `offbook up` banner / `offbook topics` footer). *Recommend the `up` banner when no scenarios/handlers are loaded.*
- **Recommended resolution:** when `scenarios/` and `handlers/` are empty, `offbook up` prints one orientation line:
  ```
  N topics served from L1 schema-fakes (valid filler). Author behavior in
  scenarios/*.yaml (L2) or handlers/*.ts (L3). Discover topics: offbook topics
  ```
  Suppress or adjust it once ≥1 scenario/handler is loaded.
- **Acceptance:** booting with empty `scenarios/`+`handlers/` prints the orientation line naming the L1/L2/L3 split; booting with ≥1 scenario does not print the empty-state line.
- **Relates to:** `offbook-ergonomics-quick-wins.md` EQ5 (the empty-parametrized-channel diagnostic — the other half of "why is my UI blank").
- **Status:** ☑ **resolved** (2026-06-30) — the orientation line is the **`offbook up` empty-state banner** (empty `scenarios/`+`handlers/`): "N topics from L1 schema-fakes (valid filler); author behavior in scenarios/\*.yaml (L2) or handlers/\*.ts (L3); discover: offbook topics", suppressed once ≥1 scenario/handler loads. Pairs with EQ5. Folded → design §4 (cross-ref) + §9.
